User Requirement Specification

Migration of Equant.SAV2000.ComponentLibrary.MVC to .NET 8+

Version: 1.0 Date: 2026-03-26 Status: Draft Document ID: URS-SAV2000-MIG-001

2. Executive Summary

This document defines the user requirements for migrating the Equant.SAV2000.ComponentLibrary from .NET Framework 4.8 / ASP.NET MVC 5 to .NET 8+ / ASP.NET Core. The library is a 42-component server-side HTML UI toolkit used extensively across the SAV2000 application suite.

The migration must achieve zero business functionality deprecation. Every component, validator, model binder, and resource management mechanism currently in production must have a functionally equivalent implementation on the target platform. The library generates HTML on the server using a fluent builder API (Html.Sav2000().Component()) and initializes client-side jQuery plugins via inline scripts.

Key migration drivers include: end of .NET Framework 4.8 mainstream support, inability to use modern NuGet ecosystem, build tooling modernization (FxCop → Roslyn, ajaxmin → esbuild), and elimination of legacy SourceSafe SCC integration.

8. Risk Assessment

Risk severity matrix for the migration project. Each risk includes likelihood, impact, and mitigation strategy.

Critical R-001: jQuery Plugin Behavioral Differences

Likelihood: High   Impact: High

jQuery plugins (DataTables, clueTip, qTip, UI Datepicker) may behave differently with newer jQuery versions or in ASP.NET Core's rendering pipeline.

Mitigation: Pin jQuery plugin versions. Create integration tests that compare HTML output and JS initialization objects. Test all 42 components in browser.

Critical R-002: Client-Side Validation Loss

Likelihood: Medium   Impact: Critical

IClientValidatable does not exist in ASP.NET Core. All 8 custom validators must be reimplemented using IClientModelValidator.

Mitigation: Create validator adapter layer. Write comprehensive tests for all validation scenarios including edge cases.

High R-003: HtmlTextWriter Removal

Likelihood: Certain   Impact: High

System.Web.UI.HtmlTextWriter is used by every component's WriteHtml() and WriteInitScript() methods. No direct ASP.NET Core equivalent.

Mitigation: Create wrapper class that implements similar API using TagBuilder or TextWriter. Preserve method signatures where possible.

High R-004: ClientDependency Replacement

Likelihood: Certain   Impact: High

ClientDependency Framework has no ASP.NET Core port. Resource registration, deduplication, and priority ordering must be rebuilt.

Mitigation: Build custom middleware or use WebOptimizer. Preserve priority ordering semantics.

High R-005: Model Binder API Changes

Likelihood: Certain   Impact: High

ASP.NET Core model binding uses IModelBinder/IModelBinderProvider instead of DefaultModelBinder. Custom binders need full rewrite.

Mitigation: Implement IModelBinder interface. Test with identical form data to verify binding parity.

High R-006: Date/Time Parsing Differences

Likelihood: Medium   Impact: High

French/English date format parsing, UTC handling, and timezone offset logic are complex and brittle. Culture-dependent behavior may differ between .NET Framework and .NET 8.

Mitigation: Create exhaustive date parsing test suite with known inputs/outputs from production. Test both cultures.

Medium R-007: Newtonsoft.Json Serialization Changes

Likelihood: Medium   Impact: Medium

DataTable options serialization uses Newtonsoft.Json attributes ([JsonProperty], [JsonIgnore]). Migration to System.Text.Json may change serialization behavior.

Mitigation: Keep Newtonsoft.Json initially. Migrate to System.Text.Json as separate phase with comparison tests.

Medium R-008: Entity Framework Migration

Likelihood: Medium   Impact: Medium

EF 4.1 to EF Core 8.x is a major version jump. ObjectContext patterns don't exist in EF Core.

Mitigation: Isolate EF dependency. Component library has minimal direct EF usage. Focus on System.Data.DataTable compatibility.

Medium R-009: Encryption Compatibility

Likelihood: Low   Impact: High

Crypt.Encrypt used for DataTable criteria parameters. Algorithm must produce identical ciphertext for interop with existing services.

Mitigation: Document current encryption algorithm. Test encrypt/decrypt roundtrip across frameworks.

Medium R-010: Localization Architecture Change

Likelihood: Medium   Impact: Medium

ASP.NET Core uses IStringLocalizer instead of strongly-typed ApplicationStrings.ResourceName pattern.

Mitigation: Create compatibility wrapper or generate strongly-typed accessor. Maintain resx files.

Medium R-011: Build Pipeline Disruption

Likelihood: Medium   Impact: Medium

Replacing ajaxmin.bat and FxCop with modern tools requires build pipeline reconfiguration.

Mitigation: Set up parallel build pipeline. Run both old and new until parity confirmed.

Low R-012: Static File Path Changes

Likelihood: High   Impact: Low

Embedded resource URLs change to /_content/LibraryName/ paths. All hardcoded paths need updating.

Mitigation: Use path constants or configuration. Search and replace all resource URLs.

Low R-013: SourceSafe Reference Removal

Likelihood: Certain   Impact: Low

SCC properties in csproj files reference SourceSafe. These must be cleanly removed.

Mitigation: Remove all Scc* properties during csproj conversion. Already done in stub project.

Low R-014: Test Infrastructure Setup

Likelihood: Low   Impact: Medium

No existing test project. Must create from scratch with mocking framework, test data, and CI integration.

Mitigation: Use xUnit + Moq + bUnit (for Razor). Set up CI early in migration process.
